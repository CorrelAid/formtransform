# Question-type screenshots

Rendered previews of each registry question type as a respondent sees it,
cropped to the question presentation.

- `<slug>/limesurvey.png` — LimeSurvey default theme (`fruity_twentythree`).
- `<slug>/xlsform.png` — the XLSForm rendered in Enketo (ODK web form).

## Regenerating

Generated by `codegen --screenshots` (off by default — needs Docker, Node, and
Playwright with Chromium). See [`../codegen/emit_screenshots.py`](../codegen/emit_screenshots.py).

```sh
uv run codegen --screenshots                          # all types, both engines
uv run codegen --screenshots --screenshots-engine=xlsform
uv run codegen --screenshots --screenshots-types=select_one,grid
```

- LimeSurvey runs fully locally on the repo's single live stack
  ([`tests/live/limesurvey/docker-compose.yml`](../tests/live/limesurvey/docker-compose.yml),
  shared with the pytest live suite), imported via the RemoteControl API. A
  running stack is reused; otherwise one is started and torn down again. The
  survey's own base language is used (no forced `lang=`), since some examples
  are German.
- XLSForm uploads each form to the public ODK XLSForm Online + Enketo staging
  services to render — form definitions leave the machine.

## Rendering notes

- **`select_*_other`** — the "Sonstiges" (other) option is selected before the
  shot so the conditional free-text field is visible. In LimeSurvey the field is
  inline and always shown; in Enketo the follow-up question un-hides on select
  and the crop spans both.
- **`select_*_long_list`** (`select_*_from_file`) — Enketo's preview can't
  resolve the external vocabulary CSV, so for the screenshot the pipeline inlines
  the vocab as regular choices into a throwaway xlsx. The presentation matches a
  deployed from-file question once its media is attached.
